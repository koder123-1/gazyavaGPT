# gazyavaGPT — ИИ-репетитор для Telegram (Render + Supabase)

Telegram-бот на **aiogram 3**: отвечает через ИИ, помнит последние сообщения диалога,
ограничивает дневную квоту, работает в личке и группах. Webhook для Render free,
PostgreSQL для сохранения контекста, квот и пользователей после рестартов.

```
tg-bot-render/
├── bot.py           # точка входа: webhook-сервер, /health, polling для локалки
├── config.py        # настройки из переменных окружения и .env
├── ai.py            # OpenRouter / Gemini / OpenAI-compatible + понятные ошибки
├── store.py         # Postgres (asyncpg) или память для отладки
├── handlers.py      # ответы, квоты, фото, меню, /imagine и /check
├── subjects.py      # автоопределение предмета задания и правила для промпта
├── styles.py        # стили ответа: универсальный, учебный, кодерский
├── i18n.py          # языки интерфейса: ru, uk, be, en + определение языка задания
├── formatting.py    # читаемые решения: LaTeX → обычный текст, чистка «thinking» + HTML-блоки
├── files.py         # чтение документов и сборка TXT/DOCX/PDF/CSV/XLSX
├── models.py        # каталог моделей ИИ: названия и цены в звёздах
├── images.py        # генерация и редактирование картинок (pollinations/openai)
├── moderation.py    # приветствия, /rules, антифлуд и антиспам в группах
├── groupadmin.py    # кик, бан, мут, предупреждения, админка, чистка истории
├── payments.py      # пополнение запросов за Telegram Stars
├── tickets.py       # тикеты поддержки: /support, ответы саппорта, закрытие
├── roles.py         # роли: владелец, гл. админ, админ, саппорт
├── admin.py         # админ-панель: статистика, пользователи, платежи, роли
├── runtime.py       # настройки из .env + переопределения из БД
├── guards.py        # защита: язык, анти-jailbreak, точное чтение задания
├── requirements.txt
├── render.yaml      # Blueprint: free-план, переменные окружения
├── .python-version  # 3.12.6 для Render
├── .env.example
└── .gitignore
```

## Что умеет

- В личке: любой текст → ответ ИИ с учётом последних реплик.
- 🧾 Решение оформляется HTML-блоками как на gdz.ru: условие и ответ в цитатах,
  шаги жирными заголовками, формулы отдельными блоками, столбики моноширинно.
- В группе бот отвечает на `/ai вопрос`, реплай на своё сообщение, `@username`
  и прозвища «газява», «газик», «газировка» (настраивается через `BOT_ALIASES`).
- 🌍 Языки интерфейса: русский, украинский, белорусский, английский. При первом
  `/start` бот предлагает выбрать язык; сменить его можно кнопкой «🌍 Язык».
  Ответ на задание идёт на языке задания: английское упражнение — по-английски.
- После короткого `/start` почти все разделы доступны постоянными кнопками меню:
  модель, стили, проверка решения, картинка, покупка запросов, поддержка,
  обращения, файлы, язык, справка, сброс контекста, условия и (у админов) админка.
  Команды остаются доступны как быстрые альтернативы, а кнопка «☰ Меню» показывает
  то же самое inline-кнопками.
- 📷 Фото задания: читает изображение и решает по шагам (vision-модель + резервные).
- 📎 Файлы: читает TXT, MD, CSV, JSON, DOCX, PDF, XLSX; по просьбе собирает и
  отправляет TXT, DOCX, PDF, CSV, XLSX, а также файлы кода PY, HTML, CSS, JS.
  Подробнее: `/files`.
- 🖌 `/imagine описание` (или «нарисуй …») — генерирует картинку; фото с подписью
  «измени / перерисуй / фотошоп» — редактирует его по описанию.
- 👍/👎, «Проще», «Подробнее», «Похожая задача» — служебные обработчики остались в коде,
  но под ответом кнопок нет: решение выглядит как чистый текст.
- ✅ Режим «проверь решение»: `/check` или кнопка → бот ищет ошибку, а не решает заново.
- 🎯 Предмет выбирать не нужно: бот сам определяет его по заданию и меняет правила
  ответа под математику, физику, химию, языки и другие предметы.
- 🎨 `/style` или кнопка «🎨 Стили» — режим ответов: универсальный, учебный
  (репетитор объясняет по шагам) или кодерский (senior-разработчик пишет полный
  HTML/CSS/JS и Python, может собрать файл `.py`, `.html`, `.css`, `.js`).
- 🧠 `/model` — выбрать модель ИИ (DeepSeek, GPT-6, GLM, Grok…) или вернуть общую по умолчанию.
- ⭐ Кнопка «⭐ Купить запросы» или `/buy` — пополнение запросов за Telegram Stars:
  выгодные наборы либо своя сумма звёзд. Подписки на ИИ нет.
- 📄 `/terms` и `/paysupport` — условия покупки и поддержка по оплате.
- 🆘 `/support` и `/tickets` — обращения в поддержку: саппорт отвечает, пользователь видит статус.
- 👑 Роли: владелец, гл. админ (почти все права), админ, саппорт — выдаются из бота.
- 🛡 Управление группой: `/group`, `/kick`, `/ban`, `/unban`, `/mute`, `/unmute`,
  `/warn`, `/promote`, `/demote`, `/del`, `/purge`, `/info`.
- 🚫 Антиспам: ссылки, массовые упоминания, повторы и КАПС удаляются; после
  `STRIKE_LIMIT` нарушений — мут, кик или бан (настраивается).
- 👋 Приветствие новым участникам, `/rules`, антифлуд с мутом в группах.
- Админ: `/admin` — панель на кнопках (`/stats`, `/ban`, `/unban`, `/broadcast` тоже работают как команды).
- На пользователя — 30 запросов в день по умолчанию, администраторы без лимита.
- По умолчанию OpenRouter с моделью `openrouter/free`; Gemini и OpenAI — одной переменной.

## 1. Получить ключ ИИ

По умолчанию используется **OpenRouter** — доступен из большинства стран и даёт бесплатные
модели: [openrouter.ai/keys](https://openrouter.ai/keys) → войти через Google/GitHub →
**Create Key** → скопировать `sk-or-v1-...` в `AI_API_KEY`. Карта не нужна, но у бесплатных
моделей есть лимиты запросов.

Модель по умолчанию — `openrouter/free`: роутер сам выбирает доступную бесплатную модель,
поэтому бот не встанет, если одну из моделей временно отключат. Актуальный список бесплатных
моделей: `https://openrouter.ai/api/v1/models` (цена `0` в полях `pricing`).

**Про Gemini.** Ключ из [Google AI Studio](https://aistudio.google.com/app/apikey) бесплатный,
но Google блокирует запросы из ряда стран ошибкой `User location is not supported for the API use`.
Локально из такой страны Gemini не заработает — это гео-блок, а не ошибка ключа. Варианты:
остаться на OpenRouter либо запустить бота на сервере в ЕС/США (Render во Франкфурте обычно
подходит) и указать:

```text
AI_PROVIDER=gemini
AI_MODEL=gemini-3.8-flash
```

Имя модели взято из ответа Google на устаревшую `gemini-2.5-flash` («no longer available to new
users»). Доступные модели и лимиты проверяйте в AI Studio — они периодически меняются.

**Про Coarena.** [coarena.ai](https://coarena.ai) даёт один ключ ко многим моделям
(DeepSeek, Gemini, GPT, Grok, Kimi) и $5 бесплатных запросов в день. Ключ создаётся на
[coarena.ai/account/api](https://coarena.ai/account/api) и должен иметь право
`inference:write`. Настройка:

```text
AI_PROVIDER=coarena
AI_API_KEY=coa_...
AI_MODELS=auto
```

`AI_MODELS=auto` означает «взять список моделей у провайдера» (`GET /v1/models`).
Бот ротирует модели на каждый запрос, а на 429/5xx/таймауте отправляет модель
«остывать» на 90 секунд и отвечает следующей. Для фото берутся только модели с
`capabilities.vision`. Свой список можно задать явно:
`AI_MODELS=gemini-4-carbon,gpt-6-1-terra,deepseek-v4-1-flash-1017`.
`AI_MODEL_ROTATE=0` оставляет только первую модель.

**Про ReformBoss.** [api.reformboss.com/v1](https://api.reformboss.com/v1) — ещё один
OpenAI-совместимый шлюз. Ключ можно хранить отдельно от `AI_API_KEY`:

```text
AI_PROVIDER=reformboss
REFORMBOSS_API_KEY=...
AI_MODEL=deepseek-v4.1-flash-1017
AI_MODELS=deepseek-v4.1-flash-1017,gpt-6-luna,glm-5.3,grok-4.7
AI_VISION_MODELS=deepseek-v4.1-flash-1017
AI_FALLBACK_PROVIDER=coarena
```

У ReformBoss в каталоге лежат не только чат-модели, но и image/video/tts, поэтому
`AI_MODELS=auto` для чата лучше не включать — бот может выбрать модель, которая не
умеет отвечать текстом. Перечислите рабочие модели вручную (в каталоге они указаны
через дефисы: `deepseek-v4-1-flash-1017`, в `AI_MODEL` допустимо то же имя).

`AI_FALLBACK_PROVIDER` — резерв: если основной провайдер вернул дневной лимит (401),
429 или 5xx, ответ уйдёт через него. Для Coarena ключ берётся из `COARENA_API_KEY`
(или из общего `AI_API_KEY`), модели — из `GET /v1/models`.

### Выбор модели пользователем

Кнопка «🧠 Модель» в главном меню (или команда `/model`) показывает каталог из `models.py`
с ценой рядом с каждой моделью. Бесплатная DeepSeek доступна всем и стоит по
умолчанию. Платные модели открываются **один раз** за звёзды — это не подписка и не
оплата за каждый запрос: после оплаты доступ остаётся навсегда.

| Модель | ID | Цена |
|---|---|---:|
| DeepSeek V4.1 Flash | `deepseek-v4.1-flash-1017` | бесплатно |
| GPT-6 Luna | `gpt-6-luna` | 5 ⭐ |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | 4 ⭐ |
| Gemini 4 Argon | `gemini-4-argon` | 3 ⭐ |
| GLM-5.3 | `glm-5.3` | 3 ⭐ |
| Grok 4.7 | `grok-4.7` | 2 ⭐ |
| GLM-5.3 Flash | `glm-5.3-flash` | 1 ⭐ |

Цена растёт вместе с силой модели: самая мощная — 5 ⭐, вспомогательная — 1 ⭐,
бесплатная доступна всегда.

Выбор хранится в `users.model`, доступы — в `model_access`. Закрытая модель
показывается с 🔒 и открывается счётом в Stars (`send_invoice`, `XTR`, payload
`model:<id>:<stars>`). После оплаты модель сразу становится активной; повторный
`charge_id` не выдаёт доступ дважды. Возврат звёзд в `/admin → Платежи` отзывает
доступ и сбрасывает выбор, если была выбрана именно эта модель.

Админ может выдать любую модель без оплаты: `/admin → Пользователи → карточка →
🧠 Модели` (тумблеры «выдать/забрать» и сброс выбранной модели). Админы и владелец
в своём `/model` видят все модели открытыми.

Фото и картинки по-прежнему идут через vision-модель и `IMAGE_MODEL` — выбор
текстовой модели на них не влияет. Картинки через ReformBoss: `IMAGE_PROVIDER=reformboss`,
`IMAGE_MODEL=grok-imagine-image-lite` (рисует и правит фото: правка идёт через
`/images/generations` с исходником в поле `image`, потому что multipart `/images/edits`
шлюз не принимает), `IMAGE_FALLBACK=pollinations` на случай 429/503.

Особенности, из-за которых это работает стабильно:

* запрос к провайдеру ограничен 55 секундами (`IMAGE_TIMEOUT` в `images.py`): если он
  «завис», бот сразу уходит на резерв, а не держит пользователя две минуты;
* шлюз кэширует картинку по тексту промпта, поэтому к промпту добавляется случайная
  вариация и `seed` — иначе повторный `/imagine` присылал бы то же самое фото;
* под готовой картинкой есть кнопка «🖼 Ещё вариант» — она повторяет тот же промпт.

## 2. Подключить базу данных

Для развёрнутого бота используется Supabase Postgres через Session pooler. Задайте
`DATABASE_URL` в Render (локально — в `.env`); секреты не добавляйте в репозиторий.
Таблицы создаются ботом автоматически при запуске. Подробности текущего облачного
развёртывания — в [`DEPLOY_RENDER.md`](DEPLOY_RENDER.md).

Никогда не добавляйте `BOT_TOKEN`, `AI_API_KEY`, пароль БД или `.env` в публичный репозиторий.

## 3. Локальная проверка и свой ID

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` и `AI_API_KEY`.
2. Запустите (Windows PowerShell):

```powershell
cd D:\tg-bot-render
py -3.14 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python bot.py
```

`.env` читается автоматически (UTF-8 или cp1251 — оба варианта поддерживаются), так что
задавать переменные вручную не обязательно.

Без `RENDER_EXTERNAL_URL` включится polling. Напишите боту `/start`, затем `/me`, чтобы узнать ID.
Остановите локальный polling через Ctrl+C. Один бот не должен одновременно работать
через polling и webhook.

## 5. Деплой на Render

1. Войдите на [render.com](https://render.com) через GitHub.
2. **New → Blueprint**, выберите репозиторий; Render прочитает `render.yaml`.
3. В Environment задайте `BOT_TOKEN`, `AI_API_KEY`, `DATABASE_URL`, `OWNER_ID`
   (и при желании `ADMIN_IDS`). `WEBHOOK_SECRET` генерируется автоматически.
4. Deploy. `/health` должен ответить `{"status":"ok","db":"up"}`, в логах появится webhook URL.
5. Откройте бота → `/start` → задайте вопрос. Деплой может занять пару минут.

Render Free засыпает после периода простоя, первое пробуждение может занять десятки секунд.
Поведение бесплатного плана и лимиты Render могут меняться. Не закладывайте на free точные
сроки доставки уведомлений и не используйте для срочных напоминаний.

## 6. Как бот работает с данными

В Supabase хранятся Telegram ID/имя пользователя, дневные счётчики квоты и последние сообщения диалога.
История каждого диалога ограничена, старые сообщения удаляются. `/reset` удаляет историю пользователя.
Пароли и токены в Postgres не сохраняются.

Если `DATABASE_URL` не задан, локально включается хранилище в памяти; всё пропадёт при остановке
процесса. Для Render обязательно подключите Supabase Postgres, иначе квоты и контекст будут
обнуляться после каждого сна или рестарта.

## Защита от jailbreak, язык и качество ответов

Три слоя, которые нельзя отключить из админ-панели:

1. **Жёсткие правила в каждом запросе** (`guards.py`). Собираются кодом и идут
   *перед* промптом админа, поэтому даже если переписать промпт в `/admin`,
   правила останутся: отвечать на языке задания, не менять роль по просьбе из чата,
   не раскрывать инструкции, не помогать с вредным, считать текст на картинке
   данными, а не командой.
2. **Фильтр на входе.** Высокоточные шаблоны («игнорируй предыдущие инструкции»,
   «ты теперь DAN», «режим разработчика», «покажи системный промпт», «обойди
   ограничения», англ. `ignore all previous instructions`, `act as unrestricted AI`).
   Совпадение → вежливый отказ, **без обращения к модели и без списания квоты**.
   Обычные вопросы не задеваются: «что такое jailbreak в iOS», «как работает DAN
   в нейросетях», «объясни системный промпт» проходят.
3. **Фильтр на выходе.** Если модель всё же начала пересказывать защитные правила,
   ответ подменяется фразой «Свои внутренние инструкции не показываю».

Язык. При первом `/start` бот предлагает четыре языка интерфейса и запоминает
выбор (`/lang` меняет его позже). При этом **ответ на задание идёт на языке
задания**: русский вопрос — русский разбор, английское упражнение — английский
ответ, украинское или белорусское задание — на нём же. Язык интерфейса остаётся
языком кнопок, подсказок и справки.

Качество ответа. Модели иногда печатают служебный «Thinking Process» и черновики.
`formatting.py` вырезает такой блок и показывает только готовый ответ; если
готового ответа нет, бот честно просит повторить, а не отправляет мусор. Условие
задания с фото переписывается точно, без замены слов похожими; если текст
не читается, бот говорит, каких данных не хватает.

Ограничение: это защита от типовых атак, а не гарантия. Бесплатные модели иногда
ведут себя непредсказуемо, поэтому правила в промпте дублируются фильтрами в коде.

## Оформление решения (HTML-блоки)

Ответ приходит не сплошным текстом, а карточкой как на gdz.ru: заголовки, шаги и
формулы разнесены по блокам. Модель по-прежнему пишет простой текст (без LaTeX и
markdown — так требует `guards.py`), а `formatting.to_telegram_html()` превращает
его в HTML Telegram:

| Что в ответе | Как показывается |
|---|---|
| `📌 Условие:` / `🧮 Решение:` / `✅ Ответ:` | жирный заголовок с эмодзи |
| текст условия и ответа | цитата (`<blockquote>`), ответ ещё и жирным |
| строки `1)`, `2)`, `Шаг 3.` | `<b>Шаг N.</b>` + текст шага |
| строка с `=`, `<`, `≤`, `∈` | отдельный блок `<code>` |
| столбик из цифр (сложение, деление) | моноширинный `<pre>` |

`send_answer()` отправляет это с `parse_mode="HTML"`. Если Telegram не принял
разметку (например, модель всё же вставила непарный тег), тот же кусок уходит
обычным текстом — пользователь никогда не увидит «сырой» HTML. Длинный ответ
режется на части по 3000 символов, а затем ещё раз проверяется: если после
экранирования (`<` → `&lt;`) HTML-кусок превышает 3800 символов, он дробится
мельче. Лимит Telegram — 4096 символов на сообщение, поэтому запас обязателен.

Хотите другой вид — правьте `to_telegram_html()`: правила разметки собраны в одном
месте, промпт менять не нужно.

## Фото домашки, генерация и редактирование картинок

Отправьте боту фотографию задания — он прочитает изображение, разберёт условие,
решит по шагам и объяснит. Подпись к фото считается вопросом («проверь решение»,
«объясни 3-й шаг», «переведи текст»).

**Генерация.** `/imagine кот-космонавт, акварель` (также `/draw`, `/art` или
«нарисуй …») — бот пришлёт готовую картинку. Провайдер и модель меняются в `.env`:

| Провайдер | Генерация | AI-редактирование | Ключ |
|---|---|---|---|
| `pollinations` | да, бесплатно | нет (только базовые правки локально) | не нужен |
| `openrouter` | да, Gemini | да, Gemini | `AI_API_KEY` + кредиты OpenRouter |
| `gemini` | да | да | `IMAGE_API_KEY` из Google AI Studio |
| `openai` | да | да | `IMAGE_API_KEY` |

**Gemini без геоблокировки.** Google отвечает `User location is not supported`
на запросы из ряда стран, поэтому напрямую `AI_PROVIDER=gemini` локально часто
не работает. Обход — `IMAGE_PROVIDER=openrouter`: тот же Gemini
(`google/gemini-nano-banana-2.1`), но через OpenRouter, который не смотрит на
страну IP и использует уже имеющийся ключ бота. Важно: у image-моделей Gemini
**нет бесплатного тарифа**, картинка 1K стоит примерно $0.034, поэтому нужен
положительный баланс OpenRouter. Пока баланса нет, бот автоматически рисует
через `pollinations` (`IMAGE_FALLBACK=pollinations`) и пишет об этом в лог.

Для прямого Gemini по умолчанию берётся `gemini-nano-banana-2.1` и новый API
`/interactions`; если указать старую модель (`gemini-2.5-flash-image`), бот
переключится на `generateContent`. Модель и адрес меняются через `IMAGE_MODEL`
и `IMAGE_BASE_URL`.

У бесплатного `pollinations` лимит — примерно **одна картинка в 45 секунд на IP
сервера**. Если несколько человек просят картинки одновременно, бот покажет,
через сколько секунд можно повторить. Свой ключ провайдера снимает это
ограничение.

**Редактирование.** Пришлите фото с подписью, что изменить.

- На `pollinations` бесплатно и локально работают базовые правки: чёрно-белое,
  сепия, негатив, размытие, резкость, яркость, контраст, поворот, отражение,
  обрезка и размер. Фото никуда не отправляется.
- AI-правки вроде «замени фон на закат» или «перерисуй в стиле аниме» требуют
  `IMAGE_PROVIDER=openrouter`, `gemini` или `openai`. В OpenRouter это
  `/images` с `input_references` (фото уходит data-URL), у Gemini —
  `generateContent` с картинкой на входе, у OpenAI — `/images/edits`.
- Если платный провайдер недоступен (нет кредитов, сеть, лимит), бот сначала
  пробует бесплатный резерв, а для правок — локальный редактор. Если правка
  ему не по силам, честно скажет, что доступно, и не пришлёт случайную картинку.

- Принимаются фото Telegram и файлы `image/*` (jpg, png, webp) до 8 МБ.
- Документы (TXT, DOCX, PDF, XLSX и др.) идут в отдельный обработчик файлов — см. ниже.
- Ответ идёт в `AI_VISION_MODEL`; если провайдер ответил 429/403/5xx или пустотой,
  бот молча пробует резервные vision-модели из `VISION_FALLBACKS` в `ai.py`.
- Ошибка ключа (401/403) не ретраится — сразу понятное сообщение.
- Картинка списывает одну единицу дневной квоты, как обычный вопрос.
- Модель для фото меняется в `/admin → Настройки → ✏️ Модель фото`, там же — промпт.

## Файлы: чтение, правка и создание

Бот принимает документ сообщением или в ответ на файл. Подпись/вопрос становится
заданием: «сделай конспект», «исправь ошибки», «реши задания и оформи в PDF».
Без подписи бот пересказывает содержимое и выделяет главное.

**Что читает.** TXT, MD, CSV, TSV, JSON, LOG, код и разметка (`.py`, `.js`,
`.html`, `.xml`, `.yaml`, `.sql` и т.п.), DOCX, PDF с текстовым слоем, XLSX.
Лимиты: `FILE_MAX_MB` (10 МБ), `FILE_MAX_CHARS` (20 000 символов в модель),
`FILE_MAX_PDF_PAGES` (60 страниц). Длинный текст обрезается с пометкой.

**Что создаёт.** TXT, DOCX, PDF, CSV, XLSX и файлы кода PY, HTML, CSS, JS.
Формат выбирается по просьбе: «в PDF», «ворд», «excel/таблица», «csv», «txt»,
«пришли .py / html файл», «пришли файлом» (по умолчанию DOCX).
Файл собирается из готового ответа ИИ: в DOCX заголовки и шаги выделены, в PDF
используется DejaVu (`assets/DejaVuSans.ttf`) — кириллица работает и на Render,
в CSV/XLSX строки с `|`, `;` или табуляцией превращаются в таблицу.

**Как устроено.** `files.py` — чистые функции чтения/сборки, `handlers.py` —
загрузка, вызов ИИ и отправка. Обработка идёт в памяти (`BytesIO`), на диск
ничего не пишется. Тяжёлые библиотеки (`pypdf`, `python-docx`, `openpyxl`,
`fpdf2`) подключены лениво: если пакет не установлен, бот скажет об этом, а не
упадёт. Файл списывает одну единицу дневной квоты, как обычный вопрос.

**Ограничения.** Скан PDF без текстового слоя не читается — бот честно попросит
фото страницы или текст. Парольные PDF и старый `.doc` не поддерживаются.
Точное редактирование вёрстки «внутри» PDF/DOCX не делается: документ собирается
заново из текста ответа. Файлы больше `FILE_MAX_MB` отклоняются, а Telegram в
принципе не отдаёт боту файлы больше 20 МБ.

## Умный репетитор и модерация

- Решения оформляются единообразно и читаемо: `📌 Условие` → `🧮 Решение` (шаги
  `1)`, `2)`, `3)` с новой строки) → `✅ Ответ`. Формулы идут обычным текстом
  (`×`, `÷`, `√`, `≤`, `x²`, `1/2`), без LaTeX и markdown: даже если модель
  пришлёт `\frac{1}{2}` или `**жирный**`, пост-процессор `formatting.py` переведёт
  это в понятный вид. Правила записи математики зашиты в защитный промпт и в
  `DEFAULT_SYSTEM_PROMPT`, поэтому администратор не может случайно их сломать.
- Ответ приходит без лишних кнопок: только текст решения.
- `/check` или кнопка проверки включает режим ожидания: следующее текстовое сообщение
  или фото рассматривается как решение ученика. Бот объясняет ошибку и правильный шаг,
  а не просто решает задание с нуля. `/cancel` отменяет режим.
- Предмет бот определяет сам по тексту задания (`subjects.py`) и подмешивает в
  системный промпт правила математики, физики, химии, биологии, языков, информатики,
  истории, географии, литературы или обществознания. Профиль ученика не нужен и не
  хранится.
- Стиль ответа хранится в `users.style` и меняется кнопкой «🎨 Стили» или `/style`.
  «Учебный» добавляет в промпт роль репетитора (`styles.py`), «кодерский» — роль
  senior-разработчика и разрешает блоки кода. В кодерском стиле предметный блок
  отключается, а код уходит в `<pre>`; при просьбе «пришли .py / html файл» бот
  собирает `.py`, `.html`, `.css` или `.js`.
- В группе новый участник получает приветствие. `{name}` — имя участника, `{bot}` — имя бота.
- `/rules` показывает правила. В `{mute}` автоматически подставляется длительность мута.
- Антифлуд по умолчанию: более 8 сообщений за 10 секунд → удаление сообщения и мут на
  10 минут. Бот должен быть администратором группы с правами удаления сообщений и ограничения участников.
  Если этих прав нет, сообщение удаляется (если доступно), а ошибка мута записывается в лог.
- Настройки приветствия/правил: `WELCOME_TEXT` и `RULES_TEXT`; порог и окно: `FLOOD_LIMIT`,
  `FLOOD_WINDOW`, срок: `MUTE_MINUTES`.

## Управление группой

В группе у бота другой набор команд: личные покупки и тикеты там молчат
(`GROUP_DISABLED_COMMANDS`), зато доступна модерация. Бот не может быть «владельцем»
чата по правилам Telegram, но с правами администратора управляет группой полностью.

| Команда | Что делает |
|---|---|
| `/group` | панель управления и проверка, каких прав боту не хватает |
| `/kick` (реплай или ID) | исключить, но разрешить вернуться |
| `/ban` / `/unban` | заблокировать / разблокировать вход |
| `/mute 1час причина` / `/unmute` | мут: писать нельзя, сообщения удаляются до конца срока / снять мут |
| `/warn` | предупреждение; после `STRIKE_LIMIT` — наказание |
| `/promote` / `/demote` | выдать / снять админку чата (без права назначать админов) |
| `/del` | удалить сообщение, на которое ответили |
| `/purge 20` | удалить последние N сообщений |
| `/info` | карточка участника: ID, страйки, роль, доступ к боту |

Доступ к командам есть у администраторов бота и у администраторов самого чата.
Нельзя трогать других админов чата — это защита от войны с командой.

**Мут и кик по реплаю.** Ответьте на сообщение нарушителя и напишите команду.
Срок понимает человеческий формат: `30с`, `15мин`, `1час`, `2ч30м`, `1день`, `7д`,
а голое число — минуты (`/mute 30`). После срока можно причину:
`/mute 1час спам` или `/kick реклама`. Сообщение, на которое ответили, удаляется.
Пока мут активен, бот удаляет всё, что пишет нарушитель, а Telegram не даёт ему
отправлять сообщения; когда срок кончается, всё возвращается само.
Активные муты хранятся в памяти процесса: после рестарта ограничение Telegram
продолжает действовать, но автоудаление сообщений может не сработать.

**Антиспам** работает автоматически: ссылки, массовые упоминания (по умолчанию 5),
повторы одного текста и КАПС. Сообщение удаляется, нарушителю добавляется страйк;
после `STRIKE_LIMIT` (3) срабатывает `ANTISPAM_ACTION` — мут на `MUTE_MINUTES`,
кик или бан. Настройки: `ANTISPAM_*`, `STRIKE_*`. Админы бота и чата не
ограничиваются.

**Обращение.** В группе бот отвечает, если написать `/ai вопрос`, ответить
реплаем на его сообщение, упомянуть `@username` или назвать «газява», «газик»,
«газировка». Список прозвищ задаётся в `BOT_ALIASES`.

## Пополнение запросов за Telegram Stars

**Обязательная подписка.** Перед первым использованием бот в личке просит подписаться на
канал и нажать «✅ Проверить подписку». Канал задаётся в `/admin → ⚙️ Настройки →
✏️ Канал подписки` (и `✏️ Ссылка на канал`) или переменными `REQUIRED_CHANNEL` и
`REQUIRED_CHANNEL_URL` — менять можно без рестарта. Подойдёт `@username`,
`https://t.me/...` или ID `-100…`; пусто или `off` — проверка выключена.
Проверка идёт через `getChatMember`, поэтому бот должен быть добавлен в канал
администратором (или быть участником группы). Если Telegram не даёт проверить,
бот не запирает пользователей, а пишет предупреждение владельцу. Владельцы и админы
бота подписку не проходят. Проверка кешируется на 45 секунд.

Бот продаёт дополнительные запросы за внутреннюю валюту Telegram — Stars. Отдельные
платёжные ключи и модерация не нужны: счёт выставляет сам Telegram, деньги приходят боту.

- Кнопка «⭐ Купить запросы» в главном меню (или `/buy`) и кнопка пополнения
  в сообщении об исчерпанном лимите.
- **Наборы выгоднее курса:** 50 запросов — 3 ⭐, 150 — 8 ⭐, 300 — 14 ⭐.
  Можно ввести свою сумму звёзд от 1 до 10 000: базовый курс — `1 ⭐ = 10 запросов`.
- Наборы и курс меняются в `/admin → Настройки` (`✏️ Тарифы Stars`, `✏️ Курс за звезду`)
  или переменными `STAR_PACKAGES` / `STAR_RATE` — без рестарта.
- Купленные запросы хранятся в `users.bonus_requests` и тратятся только после дневного
  лимита. Каждый платёж записан в таблицу `payments`.
- Повторный вебхук от Telegram не начислит дважды: `telegram_payment_charge_id` уникален.
- Перед оплатой бот проверяет, что тариф/курс и сумма совпадают с настройками.
- `/terms` и кнопка «📄 Условия» — условия покупки; `/paysupport` и кнопка «✉️ Поддержка» —
  создают Тикет с темой «Оплата»: его видят саппорт и админы, ответ приходит пользователю в личку.
- Админ получает уведомление о каждой покупке; итоги и последние платежи — в
  `/admin → ⭐ Платежи`. У каждого платежа есть кнопка «↩️ Вернуть звёзды»:
  вызывается `refundStarPayment`, запросы списываются с бонусного баланса.
- `PAYMENTS_ENABLED=0` полностью убирает продажу.

Звёзды копятся на балансе бота; вывод — через @BotFather по правилам Telegram
(доступен не сразу после первой продажи). Для проверки удобно временно поставить
тариф `1:1` и купить один запрос.

## Роли и доступ

Владелец задаётся переменной `OWNER_ID`. Остальные роли хранятся в таблице `roles` и
выдаются прямо из бота: `/admin → 👑 Роли → ➕ Выдать роль по ID`.

| Роль | Права |
|---|---|
| 👑 **Владелец** | всё; задаётся только через `OWNER_ID`, из бота не меняется |
| 👑 **Гл. админ** | почти всё, что владелец: админка, пользователи, платежи, настройки, роли, тикеты |
| 🛡 **Админ** | админка, пользователи, бан, рассылка, настройки, платежи, тикеты |
| 🎫 **Саппорт** | только тикеты: читает обращения, отвечает, закрывает |

- Роли выдаёт владелец или гл. админ. Гл. админ **не может** назначать гл. админа,
  менять другого гл. админа или владельца.
- Свою роль поменять нельзя — это защита от случайной потери доступа.
- Роль из БД перекрывает `ADMIN_IDS`. Если снять роль с ID, который указан в `ADMIN_IDS`,
  админский доступ останется — уберите ID в настройках Render.
- `ADMIN_IDS` остаётся для совместимости: эти ID считаются админами, даже без роли в БД.
- Забанить можно только пользователя с ролью ниже своей; владельца и равного по роли — нельзя.
- У саппорта обычный дневной лимит ИИ; безлимит — только у админов, гл. админов и владельца.

## Тикеты поддержки

- `/support` — меню: оплата, ошибка в ответе ИИ, доступ, другое. Пользователь описывает
  проблему одним сообщением, бот создаёт обращение и уведомляет всех саппортов и админов.
- На одного пользователя — **одно открытое обращение**: следующие сообщения добавляются в него,
  а не создают новое.
- `/paysupport` и кнопка «✉️ Поддержка» в `/buy` открывают тему «Оплата».
- `/tickets` — у саппорта список открытых обращений, у обычного пользователя — свои обращения
  и их статус.
- Карточка обращения: автор, тема, время, последние сообщения. Кнопки саппорта:
  «✍️ Ответить» (текст уходит пользователю в личку) и «✅ Закрыть».
- Пользователь отвечает кнопкой «✍️ Ответить» под ответом поддержки; сообщение попадает
  в то же обращение, саппорт получает уведомление.
- Закрытое обращение нельзя дополнить: создаётся новое через `/support`.
- Всё хранится в `tickets` и `ticket_messages`, поэтому переживает рестарт Render.

## Админ-панель

Открывается командой `/admin` (или `/panel`). Доступ — у владельца, гл. админов и админов;
саппорт видит только тикеты. Кнопка «👑 Роли» есть у владельца и гл. админа.

- **📊 Статистика** — пользователи, забаненные, активные за сегодня, запросы, топ-5 по запросам,
  оценки 👍/👎, продажи звёзд, тикеты, действующие модель и лимит. Кнопка «Обновить».
- **🎫 Тикеты** — открытые обращения: список, карточка с перепиской, ответ и закрытие.
  У саппорта тот же экран открывается командой `/tickets` и не требует `/admin`.
- **👑 Роли** — список назначенных ролей и админов из `ADMIN_IDS`, выдача и снятие роли
  по Telegram ID. Доступна владельцу и гл. админу.
- **👥 Пользователи** — постраничный список (по 5) с датами активности; кнопка с ID открывает
  карточку: сегодняшний расход, всего запросов, размер истории, бонусные запросы,
  кнопки «Забанить/Разбанить», «Сбросить контекст» и «⭐ Выдать запросы» (число можно
  ввести отрицательным, чтобы списать; пользователь получает уведомление).
- **⭐ Платежи** — всего покупок, получено звёзд, продано запросов, число возвратов и
  последние 10 платежей. У невозвращённого платежа есть кнопка «↩️ #id»: подтверждение →
  `refundStarPayment` → звёзды возвращаются пользователю, запросы списываются с бонуса.
- **🔍 Найти по ID** — карточка пользователя по числовому Telegram ID.
- **📢 Рассылка** — вводите текст → предпросмотр → «Отправить». Идёт в фоне, показывает прогресс
  и итог; забаненные пропускаются, состояние кнопки снимается сразу, поэтому нет таймаута webhook.
- **⚙️ Настройки** — лимит, глубина контекста, модель и системный промпт прямо из бота.
  Сохраняются в таблицу `settings` и перекрывают значения из `.env`; кнопка
  «Вернуть значения из env» удаляет переопределения. Применяется сразу, рестарт не нужен.

Быстрые команды: `/ban 123456789`, `/unban 123456789`, `/stats`, `/broadcast`, `/cancel`.

Забаненный пользователь получает «Доступ к ассистенту закрыт администратором» и не тратит
ни ИИ-запросы, ни квоту. Забанить владельца, гл. админа или равного по роли нельзя.

## Изменить характер ассистента

Установите переменную `AI_SYSTEM_PROMPT`, например:

```text
Ты — дружелюбный помощник сообщества по настольным играм. Отвечай по-русски,
коротко; если вопрос о правилах, сначала уточняй название игры и редакцию.
```

## Типовые проблемы

| Симптом | Что проверить |
|---|---|
| `BOT_TOKEN не задан` | Render → Environment → `BOT_TOKEN`, либо заполнить `.env` |
| 401/403 при запросе к ИИ | ключ не от того провайдера: `AI_PROVIDER` и `AI_API_KEY` должны совпадать |
| 429 | квота или rate limit провайдера; проверить тариф и лимиты |
| 404 по модели | `AI_MODEL` устарел или не существует; см. каталог провайдера |
| `User location is not supported` | гео-блок Gemini: `AI_PROVIDER=openrouter` или хостинг в ЕС/США |
| `/health` показывает 503 | `DATABASE_URL`, пароль, SSL, доступность Supabase |
| `Conflict` / polling | остановить локальный polling; запускать один экземпляр бота |
| бот молчит после деплоя | Render → Logs; на Free первый запрос может разбудить сервис |
| не приходят тикеты саппорту | получатель роли ни разу не писал боту или закрыл личку; роль должна быть выдана в `/admin → 👑 Роли` |
| саппорт не видит `/admin` | так и задумано: у саппорта только `/tickets` |
| нет кнопки «👑 Роли» | нужен `OWNER_ID` или роль гл. админа; админ роли не выдаёт |
